Wiring up email receipts

The code side has been done since it merged — nothing has ever reached it. This is the real-world plumbing: an inbox, a DNS record, and two secrets.

✓ Code merged & deployed Infra not configured Zero emails received

When it's live, sending a receipt is just: type an email address into the card terminal. Square, Zeller, and Tyro will all email a receipt on request — this catches it, reads it the same way a photo does, and drops it straight into Approve.

Confirmed via Vercel's runtime logs: api/receipt-email has had zero requests in the last 7 days. The five steps below are what's missing.

1

Create an inbound stream in Postmark

postmarkapp.com

Sign up if you don't already have an account, then create a Server — Postmark's container for a stream of mail. Inside it, open Settings → Inbound and enable inbound processing.

Free tier is fine here — this is a handful of emails a month, not a marketing list.
2

Point a subdomain at it

Postmark → same Inbound settings

Still on the Inbound settings page, choose custom inbound domain (not Postmark's generic hash address — the code needs plus-addressing, e.g. receipts+ds@…, which only a custom domain preserves reliably). Use something like:

parse.duckworth.eend.app

Postmark will hand you an MX record to add — typically inbound.postmarkapp.com at priority 10.

3

Add the MX record

wherever eend.app's DNS is managed

Add the MX record Postmark just gave you, on the subdomain from step 2. It'll look like this (use the exact value Postmark shows you — this is the typical shape):

parse MX 10 inbound.postmarkapp.com
DNS can take a few minutes to an hour to propagate. Postmark's inbound settings page will show a green check once it sees the record.
4

Generate a secret, set the webhook URL

Postmark → Inbound → Webhook URL

Pick a long random string — this is the shared secret the endpoint checks, since Postmark can't cryptographically sign inbound webhooks. Anything from a password generator works:

openssl rand -hex 24

Then set Postmark's inbound webhook URL to:

https://duckworth.eend.app/api/receipt-email?secret=YOUR_SECRET_HERE

Swap YOUR_SECRET_HERE for the value you just generated — same value goes in Vercel next.

5

Add the secret to Vercel

Vercel → moritzsmith → Settings → Environment Variables

Add one new variable (Production environment):

RECEIPT_EMAIL_SECRET = <the same value from step 4>

While you're there, worth a quick check that these two already exist (the endpoint depends on both, and they should already be set from other features):

  • SUPABASE_SERVICE_ROLE_KEY — writes the receipt row
  • ANTHROPIC_API_KEY — reads the receipt out of the email text
Redeploy (or just wait for the next push) so the new env var takes effect.
6

Test it

any inbox

Send a plain-text email with a receipt-looking body to either address below, then check the Approve tab a few seconds later.

receipts+dm@parse.duckworth.eend.app
receipts+ds@parse.duckworth.eend.app

Once it's confirmed working, this is the address to type into a Square, Zeller, or Tyro terminal at checkout — or set as an auto-forward rule in an inbox for anything from squareup.com / myzeller.com / tyro.com.

Worth knowingAny address tag other than +dm or +ds is silently dropped — no error, no bounce, it just never appears. A typo in the address fails silently. And every email gets read the same generic way a photo receipt does — it isn't tuned to any one terminal's format, so a receipt with no itemised lines (many terminal receipts) comes through as a total only, same as it would from a photo.
Reference: api/receipt-email.js. Every request gets a 200 response regardless of outcome — by design, so Postmark never retries — so a silent failure only shows up in Vercel's runtime logs, not in Postmark's dashboard.
